# 検証済みの設計判断

会話上の希望ではなく、現行コード、原資料照合記録、試験で確認できた判断だけを記録する。

## D-001 標準数量総額と1単位当り単価を分離する

- 状態: **検証済み**
- 判断: 標準歩掛の総額を、そのまま1点・1km等の単価として扱わない。標準数量で除し、所定の端数処理後に積算数量を掛ける。
- 代表例: 2級基準点測量・新点10点・伐採有りは、標準10点直接費3,448,507円、1点単価344,800円、10点直接作業費3,448,000円。
- 証拠: `規定再監査報告.md`、`調査・実装メモ.md`、`tests/test-engine.js`
- 昇格: プロジェクト判断。一般ルールへの追加確認回数は管理していない。

## D-002 精度管理費の対象判定は作業コードで行う

- 状態: **検証済み**
- 判断: 作業名の部分一致で精度管理対象を推定しない。公式作業コードと項目別設定を使用する。
- 理由: 「河川」「水準」など名称の重なりで誤分類が発生した。
- 証拠: `規定再監査報告.md`、`tests/test-engine.js`

## D-003 過去年度単価と完全過去年度マスターを区別する

- 状態: **検証済み**
- 判断: 令和4～7年度プリセットは「令和8年度歩掛＋過去年度技術者単価」の比較用と表示する。当該年度の正式積算とは扱わない。
- 証拠: `data/official-role-prices.js`、`app.js`、`tests/test-role-prices.js`

## D-004 数量精度は単位別に制限する

- 状態: **検証済み**
- 判断: 点・箇所・回等の離散量は整数、km・km²・時間等の連続量は小数第3位までとする。入力、貼付け、JSON読込みで同じ正規化を使う。
- 証拠: `engine.js`、`app.js`、`tests/test-engine.js`、`tests/test-ui-static.js`

## D-005 帳票金額は画面と同じ計算結果から生成する

- 状態: **検証済み（静的結線）**
- 判断: 見積書、総括表、業務費内訳書、単価・歩掛内訳書、積算条件書は `calculateEstimate` の結果から生成し、帳票専用の別計算を持たない。印刷直前にも再生成する。
- 証拠: `app.js`、`tests/test-ui-static.js`
- 未検証: 全帳票の実PDF目視品質。検証完了まではレイアウトの正常ベースラインへ昇格しない。

## D-006 起動時は新規画面とし、前回データは明示操作で復元する

- 状態: **検証済み（静的結線）**
- 判断: 起動時の `estimate` は必ず `emptyEstimate()` で作る。ローカル自動保存データは復元候補として保持し、「前回データを復元」を押した場合だけ表示する。
- 保護: 未操作で閉じる場合は空の新規データを保存せず、前回データを上書きしない。
- 区別: 「読込」はJSONファイルの読込み、「前回データを復元」はブラウザー内自動保存の復元とする。
- 証拠: `app.js`、`index.html`、`tests/test-ui-static.js`
- 未検証: 実ブラウザーでのローカルストレージ復元操作。手動確認が完了するまでは完全検証へ昇格しない。

## D-007 公開者・免責・応援・アクセス解析を画面上で明示する

- 状態: **検証済み（静的結線）**
- 判断: 公開画面のフッターに「Ez積算／制作：株式会社アイズ測量」を小さな署名として表示し、署名を押すと黒基調の独立した応援モーダルを開く。モーダルには無料公開の説明、確認済みOFUSE応援先、ゲスト送信の案内を置く。公式サイト、参考試算で公式ソフトではない旨、免責の詳細、`DISCLAIMER.md`、積算条件書と全帳票フッターの公式資料照合注意も維持する。
- Analytics: GA4測定IDは既存Ezアイズ製品で公開使用中の`G-88B9YPJXWP`とし、公開HTTPS版で利用者が許可した場合だけ読み込む。広告保存・広告シグナルは無効にし、積算入力値を送る独自イベントを実装しない。ローカル`file:`実行では送信しない。
- 理由: 無料公開時の作成主体・非公式性・検証責任・外部送信を、利用前に利用者が確認できるようにするため。
- 証拠: `index.html`、`analytics.js`、`app.js`、`DISCLAIMER.md`、`tests/test-ui-static.js`
- 公開検証: GitHub Pagesで「Ez積算」制作署名、応援モーダル、OFUSEリンク、ゲスト送信案内、閉じる操作、免責画面への切替、同意UIを実ブラウザー確認し、拒否選択が再読込み後も保持されることを確認した。
- 未検証: 許可時のGA管理画面への着信、全端末での表示。
