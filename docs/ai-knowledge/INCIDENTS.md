# 過去の不具合と修正理由

この文書は、再発防止に必要な検証済み事例だけを記録する。コミット履歴がないため、発生版・修正版のコミットIDは不明である。

## I-001 344,800円を標準10点の総額として扱った

- 状態: **検証済み・修正済み**
- 症状: 2級基準点測量の344,800円を10点総額と誤認できる表示・計算だった。
- 原因: 標準歩掛の数量単位と、1点当り単価の区別が不足していた。
- 正しい値: 標準10点直接費3,448,507円、1点単価344,800円、10点直接作業費3,448,000円。
- 再発防止: 標準数量、標準総額、1単位単価、積算数量総額を別項目で表示・試験する。
- 証拠: `規定再監査報告.md`、`tests/test-engine.js`

## I-002 基準点測量の精度管理費から伐採人工を誤って除外した

- 状態: **検証済み・修正済み**
- 症状: 精度管理費を268,307円としていた。
- 原因: 路線測量の独立工程「伐採」の対象外規定を、基準点測量の標準歩掛内の伐採人工へ誤適用した。
- 正しい値: `(2,934,900 + 293,490) × 9%` の円未満切捨てで290,555円。
- 再発防止: 別工程の注記を名称だけで横展開せず、作業コードと表の適用範囲を照合する。
- 証拠: `規定再監査報告.md`、`tests/test-engine.js`

## I-003 名称の部分一致で精度係数を誤分類した

- 状態: **検証済み・修正済み**
- 症状: 河川、深浅、用地、復元測量等で精度管理係数または対象外判定が誤った。
- 原因: 作業名に含まれる「河川」「水準」等の語から区分を推定した。
- 修正: 公式作業コードを主キーにした項目別判定へ変更した。
- 再発防止: 名称推定ロジックを復活させない。新項目はコードと原表で追加する。
- 証拠: `規定再監査報告.md`、`調査・実装メモ.md`

## I-004 PDF表抽出で縮尺文字列を数量へ連結した

- 状態: **検証済み・修正済み**
- 症状: 現地測量の数量を5001業務、5000.1km²として扱った。
- 原因: 縮尺1/500の文字列と数量セルを機械抽出時に連結した。
- 修正: 1業務、0.1km²へ修正した。
- 再発防止: PDF抽出値は、単位・標準数量・前後見出しを含めて原表と照合する。
- 証拠: `規定再監査報告.md`、`調査・実装メモ.md`

## I-005 旅費交通費を任意手入力だけにしていた

- 状態: **検証済み・修正済み**
- 症状: 原則の旅費率計上が自動反映されなかった。
- 修正: 宿泊なし0.56%・上限23万円、宿泊あり0.83%・上限31.3万円、実費積上げを切替可能にした。
- 再発防止: 手入力を既定値にせず、基準の原則式と例外入力を分ける。
- 証拠: `engine.js`、`規定再監査報告.md`、`tests/test-engine.js`

## I-006 起動時に前回の積算を自動表示した

- 状態: **再現済み・修正済み・静的試験済み**
- 症状: ページを開くとローカル保存された前回の積算が、そのまま現在の入力画面に表示された。
- 原因: 初期化時に `estimate = loadEstimate()` を実行し、起動直後にも無条件で `persistEstimate()` を実行していた。
- 修正: 入力画面は `emptyEstimate()` で開始し、保存データは復元候補として別保持する。復元ボタンを押した場合だけ読み込む。未操作終了時の無条件保存を廃止した。
- 再発防止: T-UIで新規初期化、明示復元、未操作時の上書き防止を静的検査する。
- 証拠: 修正前後の`app.js`確認、`tests/test-ui-static.js`
- 未検証: 実ブラウザーを使った操作試験。

## I-007 スマートフォン幅で積算明細表がページ全体を横へ押し出した

- 状態: **再現済み・緩和済み・実ブラウザー部分検証済み**
- 症状: 公開HTTPS版を幅390pxで表示すると、ページの`scrollWidth`が510pxとなり、積算明細表のために画面全体が横スクロールした。
- 原因: 積算表自体には横スクロール枠があったが、CSS Grid項目の`.workspace-main`に`min-width: 0`がなく、表の最小内容幅まで親グリッドが縮まなかった。
- 修正: `.workspace-main, .master-layout`へ`min-width: 0`を追加し、広い表は`.table-scroll`内だけで横スクロールさせる。
- 検証結果: 公開版の幅390pxで、本文幅375px、積算表の表示枠345px・内部内容505px、タブ2段折返しを確認した。表は専用枠内で横スクロールする。自動計測上の`documentElement.scrollWidth`は485pxを報告しており、全ブラウザーでページ根元の横移動が完全に解消したとは確定していない。
- 再発防止: T-UIで親グリッドの最小幅解除、表のレイアウト封じ込め、タブ折返しを静的検査する。別ブラウザーの実機確認が完了するまで「完全修正」へ昇格しない。
- 証拠: 公開版の幅390px実測、`styles.css`、`tests/test-ui-static.js`

補足: 修正直後の公開確認ではブラウザーが旧`styles.css`を再利用したため、HTMLからCSS・JavaScriptを版番号付きURLで参照し、公開更新時のキャッシュ混在を防止した。

## I-008 資料取込の正規化で小数点を削除した

- 状態: **再現済み・修正済み・固定値試験済み**
- 症状: 初期実装で「技師（A） 2.5人日」を25人日として候補化した。
- 原因: 名称照合用の空白・記号除去処理で小数点まで削除し、その文字列を人工の数値抽出にも使っていた。
- 修正: 名称照合用の正規化でも小数点を保持し、2.5、0.75、1.25人日の固定値試験を追加した。
- 再発防止: OCR・PDFの正規化変更時はT-DOC-IMPORTで整数、少数、縮尺、丸数字を同時検査する。
- 証拠: `document-import-engine.js`、`tests/test-document-import.js`
