# 外部知能インデックス

このディレクトリは、再調査や不具合再発を避けるための、検証可能なプロジェクト知識を保存する。会話ログの要約場所ではない。

## 状態ラベル

| 状態 | 意味 | 利用範囲 |
|---|---|---|
| 観察 | ファイル、画面、ログなどで一度確認した事実。再現性は未確認 | 調査の入口。仕様根拠にはしない |
| 再現済み | 手順と条件を記録し、同じ現象を再現した | 不具合・挙動の根拠にできる |
| 検証済み | 原資料、固定値、テストなどの再実行可能な証拠で確認した | 実装・回帰判定に使える |
| 仮説 | 原因や仕様の推測。未確認 | 実装根拠にしない |
| 廃止 | 現在は採用しない知識。廃止理由と後継を残す | 再採用を防ぐためだけに読む |

## 必要なときだけ読む文書

| 作業 | 読む文書 |
|---|---|
| 現在の構成・未解決事項を把握する | [PROJECT_STATE.md](PROJECT_STATE.md) |
| 修正前に正常版・ハッシュ・試験結果を確認する | [VERIFIED_BASELINES.md](VERIFIED_BASELINES.md) |
| 計算・マスター・帳票の採用方針を確認する | [DECISIONS.md](DECISIONS.md) |
| 過去の誤計算・原因・修正理由を確認する | [INCIDENTS.md](INCIDENTS.md) |
| 変更内容に対応する試験を選ぶ | [TEST_MATRIX.md](TEST_MATRIX.md) |
| 新しい知識を記録する | [ENTRY_TEMPLATE.md](ENTRY_TEMPLATE.md) |

## 読み方

1. Git状態と正常ベースラインを先に確認する。
2. 今回変更する領域に対応する文書だけ読む。
3. 記載の状態、証拠、検証日、対象バージョンを確認する。
4. 「仮説」「観察」だけの記載を確定仕様として実装しない。
5. 実装後、再実行できる試験に合格した内容だけを更新する。

## 知識の昇格

単発の知見は個別記録に留める。同じ知見が、別の案件・別の資料・別のテストなど独立した証拠で複数回確認された場合に限り、プロジェクト共通ルールへの昇格を検討する。昇格時は確認回数と証拠IDを残す。

ユーザーの会話は要求を理解する材料であり、それ自体を「検証済み仕様」として登録しない。秘密情報、個人情報、顧客情報、実案件の数量・金額は登録しない。
